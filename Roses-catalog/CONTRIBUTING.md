# 🤝 Как внести вклад в «Азбуку Роз»

Спасибо, что заглянули! Этот проект — пет-проект одного разработчика, но я всегда рада фидбэку, багам и идеям. Ниже — короткие правила, чтобы всем было комфортно.

---

## 🐛 Нашли баг?

1. Проверьте, не описан ли он уже в разделе [Issues](https://github.com/NatalyaSvetlakova/Roses-catalog/issues).
2. Если нет — создайте новый Issue.
3. В заголовке укажите суть: `[Bug] Слайдер не листается на iOS Safari`.
4. В теле опишите:
   - **Что вы ожидали** — коротко.
   - **Что произошло на самом деле**.
   - **Шаги воспроизведения** — по пунктам.
   - **Окружение**: браузер, ОС, ширина окна.
   - **Скриншот или видео** — если возможно.

---

## 💡 Есть идея?

1. Создайте Issue с префиксом `[Feature]`.
2. Опишите:
   - **Какую задачу решает идея** — «болит» у пользователя.
   - **Как вы её видите** — в двух словах.
   - **Альтернативы**, которые вы рассматривали.
3. Дождитесь ответа, прежде чем писать код — чтобы не потратить время зря.

---

## 🔧 Хочу предложить Pull Request

### Перед началом
- Обсудите изменение через Issue — так мы точно поймём друг друга.
- Для мелких правок (опечатки, форматирование) Issue можно не заводить.

### Процесс

1. **Форкните** репозиторий и клонируйте свой форк:
   ```bash
   git clone https://github.com/<ваш-ник>/Roses-catalog.git
   cd Roses-catalog
   ```

2. **Создайте ветку** с понятным именем:
   ```bash
   git checkout -b fix/slider-mobile
   # или
   git checkout -b feature/dark-theme-print
   ```

3. **Внесите изменения**. Держитесь стиля проекта:
   - **CSS**: один блок — одно назначение. Порядок свойств: позиционирование → бокс-модель → типографика → цвет → эффекты.
   - **JS**: `camelCase` для переменных, `PascalCase` для классов (если появятся), ES6+ синтаксис.
   - **HTML**: семантические теги, ARIA-атрибуты для интерактива.
   - **Комментарии** — на русском, коротко и по делу.
   - **Отступы** — 2 пробела (как в существующем коде).
   - **Точка с запятой** в CSS и JS — обязательна.

4. **Проверьте локально**:
   - Откройте через Live Server (`http://127.0.0.1:5500/`).
   - Прогоните сценарии: переключение темы, фильтры, избранное, отзывы.
   - Проверьте адаптив: 320px, 480px, 768px, 1024px, 1440px.
   - Проверьте в Chrome, Firefox и Safari (если есть возможность).

5. **Закоммитьте** по правилам [Conventional Commits](https://www.conventionalcommits.org/):
   ```
   feat: добавить сортировку по аромату
   fix: поправить скролл сайдбара на мобильных
   style: унифицировать отступы в карточках
   docs: обновить README
   refactor: вынести логику фильтров в модуль
   chore: обновить .gitignore
   ```

6. **Запушьте** и откройте Pull Request:
   ```bash
   git push origin fix/slider-mobile
   ```

7. В описании PR укажите:
   - Ссылку на Issue: `Closes #12`.
   - Что именно изменили и почему.
   - Скриншоты «до / после», если менялся UI.

## ✅ Чек-лист перед PR

- [ ] Код протестирован локально.
- [ ] Нет `console.log` в продакшн-коде.
- [ ] Нет закомментированных кусков кода.
- [ ] Не сломаны существующие сценарии.
- [ ] Проверены светлая и тёмная темы.
- [ ] Проверен адаптив на мобильных.
- [ ] Коммиты осмысленные, в едином стиле.

---

## 🎨 Что особенно приветствуется

- Улучшение **доступности** (ARIA, фокус, контраст).
- Оптимизация **производительности** (lazy-load, размер изображений).
- Улучшение **тёмной темы** — она ещё развивается.
- Улучшение **адаптива** на необычных разрешениях.

---

## 🚫 Что не принимается

- Переписывание проекта на React/Vue/Svelte — это осознанно ванильный проект.
- Добавление библиотек «для красоты» без обсуждения.
- Массовые автоправки форматирования без функциональных изменений.
- Изменение брендовых цветов (`--color-primary`, `--color-secondary`) без согласования.

---

## 📜 Кодекс поведения

- Общаемся уважительно, без перехода на личности.
- Критикуем код, а не автора.
- Помогаем новичкам — все когда-то начинали.
- Отказываемся от токсичности, дискриминации и спама.

Нарушение кодекса — блокировка без предупреждения.

---
